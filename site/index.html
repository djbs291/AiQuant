Quantitative research engine

AiQuant MVP

A fast C++ engine for algorithmic-trading research — exposed as a simple HTTP API. Send price data, get candles, indicators, a trained model and a backtest back.

Quickstart View on GitHub

What it does

The whole pipeline, from raw ticks to a backtested signal, behind one request.

Ticks → candles

Resamples raw tick data into OHLCV candles at S1–H1 timeframes.

Indicators

EMA, RSI, MACD, Bollinger, ATR, ADX, Stochastic, VWAP, Z-Score, Momentum — validated against TA-Lib.

Models

Ridge, online SGD, or an MLP predict the next close-to-close move. Trained on your data, per request.

Backtest

A rule + model signal engine, reported out of sample with the in-sample stretch beside it.

Quickstart

Every endpoint but /health needs your API key in an X-API-Key header.

# Is the service up? (no key needed)
curl https://aiquant-http-ukqi.onrender.com/health
{"status": "ok"}

# Back-test your own data inline: send a tick CSV + a scenario config.
curl -X POST https://aiquant-http-ukqi.onrender.com/run-inline \
  -H "X-API-Key: YOUR_KEY" \
  -d '{"ticks_csv": "Timestamp,symbol,price,volume\n...", "config": "tf = M5\nmodel = ridge"}'

# Evaluate the signal engine on one snapshot.
curl -X POST https://aiquant-http-ukqi.onrender.com/signal \
  -H "X-API-Key: YOUR_KEY" \
  -d '{"close":100,"rsi":20,"ema_fast":11,"ema_slow":10,"prediction":0.5}'
{"signal": "Buy", "score": 2.5, "reason": "RSI<=buy EMA+ ML+ "}

Endpoints

JSON in, JSON out. Full reference in the README.

Method & pathWhat it does
GET /healthLiveness check. Open, no key.
POST /run-inlineFull pipeline on data you send in the request: candles, indicators, model, out-of-sample backtest.
POST /predictApply a trained model to one set of feature values.
POST /signalRun the rule + model signal engine on one snapshot.
